# QDII Radar 年初至今（YTD）涨跌幅设计

## 背景
当前列表中的 `oneYearChange` / “1年期” 列需要改为“今年来”，口径统一为年初至今（YTD）涨跌幅。

用户已确认：
- 指标名称改为：`今年来`
- 指标口径改为：YTD（年初至今）
- 所有基金统一按**累计净值**计算
- 采用最小改动方案：继续复用现有 `oneYearChange` 字段承载新语义，后续如需再单独清理命名

## 目标
1. 前端展示“今年来”而不是“1年期”
2. 后端返回的 `oneYearChange` 实际表示 YTD 百分比涨跌幅
3. 全部基金统一按累计净值计算，不再对 ETF/LOF 使用交易价格历史
4. 清理旧缓存，避免历史 1 年期结果污染新口径

## 非目标
1. 本次不重命名 API 字段 `oneYearChange`
2. 本次不新增 `ytdChange` 字段
3. 本次不做更大范围的历史指标体系重构
4. 本次不调整其他列或排序规则

## 方案选择
采用**方案 A：直接把现有 `oneYearChange` 字段重定义为“今年来”**。

原因：
- 改动最小，回归风险最低
- 前后端接口无需大改
- 可以最快替换错误业务口径

代价：
- 内部字段名与业务语义暂时不一致，保留技术债

## 业务定义
### 指标定义
今年来涨跌幅（YTD）定义为：

`(当前累计净值 - 今年首个可用净值日的累计净值) / 年初基准累计净值 × 100`

### 基准日规则
- 目标基准时间点为当年 `1月1日`
- 实际基准值取 **当年 1 月 1 日之后的第一个可用净值日** 对应的累计净值
- 若当年无足够累计净值数据，则该基金 `available = false`

### 数据口径
- 全部基金统一使用 AKShare 的累计净值历史数据
- ETF/LOF 不再走交易价格历史路径
- 使用累计净值而不是单位净值，以包含分红影响

## 设计
### 后端
#### 1. 保留对外字段，替换内部语义
继续复用：
- `oneYearChange`
- `oneYearChangeAvailable`
- `get_one_year_change()`
- `get_cached_one_year_change()`

但这些逻辑实际改为“今年来”。本次不改函数名，避免扩大改动面。

#### 2. 历史计算逻辑调整
当前 `fetch_historical_nav_eastmoney()` 是围绕近 365 天目标点寻找基准值，需要调整为：
- 读取累计净值走势
- 取最新一条作为当前累计净值
- 过滤出当前年份的数据
- 取当前年份第一条记录作为年初基准累计净值
- 计算 YTD 百分比

建议返回结构仍兼容现有调用方，例如：
- `nav_1_year_ago` 字段暂时继续复用为“年初基准累计净值”存储值，或在函数内局部重命名后再映射回旧结构
- `percentage_change` 表示 YTD 百分比
- `days_found` 表示用于本年度计算的记录数

#### 3. ETF 历史价格路径停用
`get_one_year_change(code, is_exchange_traded)` 内不再根据 `is_exchange_traded` 分流到 `fetch_historical_etf_price()`。
统一调用累计净值历史函数。

`fetch_historical_etf_price()` 可以先保留未调用状态，避免本次删除引发额外回归风险。

#### 4. 缓存处理
继续使用 `historical_nav_cache` 表，但缓存内容语义从“1年期”切换为“今年来”。

实施时必须：
- 清空 `historical_nav_cache`
- 让系统按新口径重建缓存

这是必须步骤，否则旧缓存会继续返回错误语义的数据。

### 前端
#### 展示
- 表头文案：`1年期` → `今年来`
- 其他显示逻辑保持不变：
  - 有值显示百分比
  - 无值显示 `—`
  - 正负颜色逻辑不变

#### 排序
继续按 `oneYearChange` 字段排序。
排序规则和无数据置底规则保持不变。

### 文档
需要同步修正文档中关于“1年期 / cumulative NAV-based 1-year performance”的描述，至少更新：
- `CLAUDE.md` 中相关字段说明
- 如有直接用户可见的架构/说明文档提到该列，也应同步修正

## 测试策略
### 后端测试
1. **YTD 基准值测试**
   - 构造跨年累计净值数据
   - 验证取当前年份第一条累计净值作为基准，而不是 365 天前最近点

2. **ETF 统一走累计净值路径测试**
   - 验证 `is_exchange_traded=True` 时也不会调用 ETF 价格历史函数
   - 验证仍走累计净值历史函数

3. **无当年数据测试**
   - 若当前年份无可用累计净值记录，返回 `available = false`

4. **现有接口回归**
   - `/api/funds` 仍返回 `oneYearChange` 与 `oneYearChangeAvailable`
   - 前端契约不变

### 前端验证
1. 列标题显示“今年来”
2. 有数据时正常显示百分比
3. 无数据时显示 `—`
4. 排序仍正常工作

3. 更新前端列标题文案
4. 更新相关注释与文档说明
5. 清空 `historical_nav_cache`
6. 运行测试并做接口抽查

## 风险与缓解
### 风险 1：字段名与语义不一致
- 风险：`oneYearChange` 实际变成 YTD，后续维护容易误解
- 缓解：本次同步更新注释和文档，后续单独安排字段命名清理

### 风险 2：旧缓存污染
- 风险：用户仍看到旧 1 年期值
- 缓解：上线前主动清空 `historical_nav_cache`

### 风险 3：部分基金当年数据不足
- 风险：今年新基金或异常基金无可用值
- 缓解：保持 `available = false`，前端显示 `—`

## 验收标准
1. 页面列名显示为“今年来”
2. 同一只基金“今年来”值按累计净值 YTD 公式计算
3. ETF/LOF 与场外基金口径一致
4. `/api/funds` 契约不变
5. 测试通过，且旧缓存已清空
